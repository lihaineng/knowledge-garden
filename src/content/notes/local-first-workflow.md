这套系统把“写作”和“发布”分开：日常只需关心本地文件，发布由自动化流程完成。

## 日常写作

在 `src/content/notes/` 中新建 Markdown 文件，补齐标题、描述、日期和标签。使用任意喜欢的编辑器写作，本地预览只是可选步骤。

## 安全备份

一次 Git 提交代表一个可以返回的时间点。推送到 GitHub 后，本地硬盘和远程仓库各保留一份历史。

## 自动发布

推送到 `main` 分支会触发 GitHub Actions。它检查内容、构建静态页面、生成全文搜索索引，最后更新 GitHub Pages。

## 草稿不会泄露到站点

将 frontmatter 中的 `draft` 设置为 `true`，这篇笔记就不会生成公开页面，也不会进入搜索索引与站点地图。

> 注意：公开 GitHub 仓库中的源文件本身仍然可见。真正私密的内容不应放进这个仓库。
